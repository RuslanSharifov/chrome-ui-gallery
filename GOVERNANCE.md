# Community governance

[← Home](./README.md) · [Contribution rules](./CONTRIBUTING.md)

## Who can participate?

Anyone can fork the public repository and propose changes using pull requests. Direct write access to the main branch is **not required**.

## Decision-making

Repository maintainers review proposals for security, quality, usability, licensing and consistency. The repository owner is the final decision-maker on merge and release decisions. Reviewers should explain rejections or requested changes where feasible.

## Responsibilities

- **Contributors:** submit work they have rights to share, document permissions, test and respect the code of conduct.
- **Reviewers:** evaluate technical and community risks, help new contributors and request actionable fixes.
- **Maintainers:** maintain navigation, protect main, triage vulnerabilities and avoid unreviewed third-party content.

## Becoming a maintainer

Repeated, trusted contributions and constructive reviews can lead to a maintainer invitation; this is discretionary, not automatic.

## Repository settings recommended for owner

Use GitHub Settings → Rules → Rulesets to protect **main**: require pull requests, review approval and the **Validate gallery** status check once it has successfully run. Configure branch protection in the GitHub UI; merely adding a workflow does not activate these repository settings.
